End-to-end geospatial analytics pipeline on Azure Databricks — from raw network event ingestion to location-based data powering advertisement campaign targeting and analytics.

Solution Overview

This platform replaced a deprecated legacy geolocation system with a fully automated pipeline that ingests near-real-time network events via AutoLoader, enriches data with Uber H3 geospatial indexing, Voronoi/sub-Voronoi cell-site mapping, and POI reference data — maintained via SCD Type 2 monthly batch loads tracked at the Silver layer — then aggregates enriched results into Gold ad campaign segment tables. Parent-child notebook orchestration enables concurrent multi-campaign execution at scale.

Orchestration Pattern

A parent notebook dynamically generates child notebook job submissions per campaign using dbutils.notebook.run() with concurrent threading (Python ThreadPoolExecutor). Each child processes one campaign segment independently, with configurable timeout, retry logic via tenacity, and granular status tracking written back to a control Delta table.

Parent Notebook ├── Load campaign config from Delta control table ├── ThreadPoolExecutor(max_workers=N) │ ├── submit → child_notebook(campaign_id=001, timeout=3600) │ ├── submit → child_notebook(campaign_id=002, timeout=3600) │ └── submit → child_notebook(campaign_id=00N, timeout=3600) └── Collect futures → write execution status to control table Child Notebook ├── Read campaign parameters ├── Process and Write enriched output → Gold └── Write status (SUCCESS / FAILED / PARTIAL) → control table

SCD Type 2 Implementation

Applied to the Silver POI reference table (monthly batch load). POI attributes — name, category, geometry, and type — are tracked over time. Each monthly refresh detects attribute changes via MD5 checksum and creates a new version, preserving full audit history with effective dates.

Spark Performance Optimisations

Compute Tuning

  • Adaptive Query Execution (AQE) — dynamic partition coalescing
  • Photon vectorized engine for Delta scan & joins
  • Optimise-write to minimize small file issues
  • Auto-scaling job clusters

Storage Tuning

  • Liquid Clustering on geo spatial join keys
  • OPTIMIZE & VACUUM scheduled jobs
  • Partition pruning on ingest_date
