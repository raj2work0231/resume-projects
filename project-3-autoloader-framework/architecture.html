AutoLoader File-Notification Multiplexer Pipeline

Files land on ADLS Gen2; Azure Event Grid fires file notifications to Azure Queue Storage. AutoLoader (cloudFiles, useNotifications=true) picks up new files without directory listing and streams records into a centralised Multiplexer Delta table. Dedicated streaming jobs then apply SCD Type 1 or SCD Type 2 to downstream tables — all driven by a single metadata config.

Solution Overview

This pipeline ingests files from multiple ADLS Gen2 landing zones using AutoLoader file-notification mode: Azure Event Grid subscribes to blob-created events and routes them to an Azure Queue Storage. AutoLoader polls the queue to discover new files instantly — no costly directory listing. Each file’s records are enriched with dataset_id, target_table, and CDC operation type (from config or payload), then streamed into a single centralised Multiplexer Delta table. A separate streaming job per dataset reads from the Multiplexer via readStream and applies SCD Type 1 (latest-wins MERGE) or SCD Type 2 (expire + insert with eff_from / eff_to) to the downstream Silver table — enabling near-real-time propagation without scheduled batch jobs.

Pipeline Stage Details

Stage 1 — AutoLoader File-Notification (Event Grid + Queue Storage)

Azure Event Grid subscribes to ADLS Gen2 blob-created events and routes each notification to Azure Queue Storage. AutoLoader (cloudFiles.useNotifications=true) polls the queue to discover and ingest new files — eliminating directory listing and scaling to millions of files without performance degradation.

cloudFiles.useNotifications=true Azure Event Grid (blob-created) Azure Queue Storage (event queue) No directory listing overhead Schema inference + evolution Checkpoint per dataset

Stage 2 — Multiplexer Delta Table (Central Routing Hub)

All file-based datasets are streamed into a single Multiplexer Delta table. Each record is enriched with: dataset_id, target_table (resolved from config), operation (INSERT/UPDATE/DELETE from payload field or default INSERT), and the full source file path. Enables a single AutoLoader engine to serve all datasets.

dataset_id column target_table column operation: INSERT / UPDATE / DELETE source_file path row_hash (MD5 change detection) Partitioned by ingest_date / dataset_id

File Tracking Delta Table

file_path, file_size, status PENDING / PROCESSING / DONE / FAILED Retry count tracking Drives recovery & reprocessing

Schema Evolution Handler

addNewColumns mode mergeSchema on Multiplexer write Type inference overrides Schema version audit logging

Stage 3 — Streaming Downstream Jobs (SCD1 / SCD2 per dataset)

One streaming job per active dataset reads from the Multiplexer table via readStream.format("delta") filtered on dataset_id. Each micro-batch applies SCD Type 1 (latest-wins MERGE) or SCD Type 2 (expire + insert with eff_from / eff_to) to the downstream Silver table via foreachBatch, with DELETE operations handled as hard-deletes (SCD1) or soft-closes (SCD2).

readStream from Multiplexer Filtered by dataset_id foreachBatch SCD merge SCD1: latest-wins MERGE SCD2: eff_from / eff_to / crnt_flag DELETE: hard-delete (SCD1) / soft-close (SCD2) Independent checkpoint per dataset

Impact & Outcomes

  • Event Grid file-notification eliminates directory listing — near-instant file detection at any landing scale
  • Multiplexer pattern routes all file-based datasets through one AutoLoader engine — no per-dataset notebooks
  • Streaming downstream jobs propagate changes in near-real-time without scheduled batch overhead
  • SCD type (1 or 2) is business-requirement driven per dataset — configured in metadata, not hardcoded
  • Schema evolution handler prevents pipeline failures from upstream schema changes
  • File tracking table enables reliable recovery and audit for every ingested file
